# Research Method

## 1. Purpose

This document defines the scientific methodology used throughout the Roman Dodecahedron Open Research Project (RDORP).

Its purpose is to ensure that all research activities are:

* evidence-based,
* reproducible,
* transparent,
* traceable,
* and independent of any preferred hypothesis.

This document governs how information enters the repository and how it is transformed into knowledge.

---

# 2. Guiding Principles

The project follows five fundamental principles.

## Evidence Before Interpretation

Observations are recorded before conclusions are drawn.

Interpretations must never modify or replace observations.

---

## Traceability

Every recorded value should be traceable to one or more identifiable sources.

Whenever possible, references should point to the original publication, museum record, excavation report, or measured artifact.

---

## Reproducibility

Independent researchers should be able to reproduce every analysis using:

* repository data,
* documented workflows,
* published scripts,
* and cited references.

---

## Transparency

Unknown information remains unknown.

Estimated values must always be identified as estimates.

Derived values must be distinguishable from directly observed values.

---

## Neutrality

The repository does not attempt to prove a specific theory.

The project evaluates hypotheses only after sufficient evidence has been collected.

---

# 3. Research Workflow

Every research activity follows the same sequence.

## Step 1 — Evidence Collection

Collect information from reliable sources.

Possible sources include:

* archaeological publications
* excavation reports
* museum collections
* peer-reviewed journals
* conference proceedings
* books
* official heritage organizations

No interpretation is performed during this stage.

---

## Step 2 — Source Verification

Each source is evaluated for:

* authenticity
* completeness
* publication status
* citation quality
* relevance

Each source receives a confidence classification as defined in **RDORP-007 Source Evaluation**.

---

## Step 3 — Data Extraction

Extract only factual information.

Examples include:

* dimensions
* measurements
* inventory numbers
* discovery locations
* dates
* photographs
* descriptions
* archaeological context

No inferred values are added during extraction.

---

## Step 4 — Data Normalization

Normalize the extracted data into the repository schema.

Typical normalization tasks include:

* standardizing units
* harmonizing place names
* converting coordinates
* resolving duplicate identifiers
* applying controlled vocabularies

Normalization must not alter the original meaning of the data.

---

## Step 5 — Data Validation

Each record is checked for:

* completeness
* consistency
* duplicate entries
* conflicting measurements
* missing references
* invalid values

Validation results should be documented.

---

## Step 6 — Analysis

Only validated data may be analyzed.

Possible analytical methods include:

* descriptive statistics
* comparative analysis
* GIS
* graph analysis
* geometric analysis
* engineering assessment
* computational methods

Analytical results are stored separately from the primary evidence.

---

## Step 7 — Experimental Archaeology

Experimental work is performed only after the available evidence has been documented.

Experiments should:

* be repeatable,
* define objectives,
* describe materials,
* document procedures,
* record measurements,
* preserve raw observations.

Experimental conclusions remain separate from archaeological observations.

---

## Step 8 — Hypothesis Evaluation

Hypotheses are evaluated using the complete body of available evidence.

Each hypothesis should:

* define its assumptions,
* identify expected observations,
* identify contradictory evidence,
* state its limitations,
* remain open to revision.

---

# 4. Data Categories

The repository distinguishes between four categories of information.

## Observed Data

Directly recorded from an artifact or authoritative source.

Examples:

* dimensions
* inventory numbers
* excavation context

---

## Derived Data

Generated from observed data.

Examples:

* calculated ratios
* statistical summaries
* graph metrics
* geometric calculations

Derived data must document the method used to generate it.

---

## Experimental Data

Produced through controlled testing.

Examples:

* load measurements
* wear observations
* assembly times
* structural stability

---

## Interpretive Data

Represents proposed explanations.

Examples:

* functional hypotheses
* engineering interpretations
* historical scenarios

Interpretive data must never overwrite observed or derived data.

---

# 5. Research Integrity

The repository adopts the following rules.

* Unknown values remain empty.
* Contradictory sources are preserved.
* Every correction is versioned.
* Original evidence is never deleted.
* Every modification should be attributable.

---

# 6. Reproducible Research

Whenever practical, analyses should be generated automatically from repository data.

Examples include:

* statistical reports
* GIS maps
* engineering summaries
* specimen tables
* charts
* figures

Manual editing of generated outputs should be avoided.

---

# 7. Documentation Standards

Every document should:

* define its purpose,
* specify its scope,
* reference related documents,
* maintain a revision history.

Every dataset should include:

* field definitions,
* units,
* controlled vocabularies,
* validation rules.

---

# 8. Review Process

Research contributions should undergo review before acceptance.

The review should verify:

* source quality,
* data accuracy,
* schema compliance,
* citation completeness,
* reproducibility.

---

# 9. Success Criteria

The methodology is considered successful when:

* independent researchers can reproduce repository analyses,
* every stored fact can be traced to its source,
* interpretations remain distinguishable from observations,
* new data can be incorporated without altering previous evidence.
